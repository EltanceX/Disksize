# 阶段 6：目录与大文件界面

日期：2026-11-15

## 界面与容量口径

首页显示普通应用挂载视图中的存储卷、容量采样时间和最近 20 个索引会话。点击卷入口填入扫描路径，普通/root 模式、权限引导和任务取消继续使用原有扫描设置。Root 入口取自已授权 root 进程的挂载视图，普通启动不会请求 root。

从最近会话或“浏览目录与大文件”进入空间浏览。界面参考 TreeSize 的文件夹层级、黄色容量条、容量排序和多口径展示，适配 Android 触摸操作。手机使用单列和详情抽屉，宽度达到 1050 且字体适合时显示详情分栏；大字体退回单列布局。

面包屑和系统返回支持逐级导航；目录列表展示直接子项，“大文件”展示当前目录及其后代中的普通文件。支持逻辑大小/报告占用切换，以及两种容量降序、原始名称字节升序。分页控件固定在底部，每页 50 项，前后翻页替换当前页面并回到顶部。详情显示准确字节数、权限、UID/GID、inode、挂载、链接数、修改时间、原始路径和当前节点的问题分页。

容量、硬链接归属及目录自身 blocks 沿用阶段 5 语义。容量条的分母是当前目录在所选口径下的已知总量；暂定统计及零分母不绘制误导比例。未知元数据、不完整子树、不可访问项、硬链接共享、符号链接和主动跳过均单独标注。共享硬链接可以在列表中显示零贡献，同时在详情保留原始大小和原始 blocks。

名称保留原始字节，显示转义控制符和双向文本控制符。可解码路径复制真实 UTF-8 内容，包括换行；无效 UTF-8 路径复制完整路径的十六进制字节，并明确提示格式。复制以索引会话记录的规范化根路径为准，Android 路径别名可能与输入文字不同。

“卷与扫描范围”显示扫描开始/结束时间、卷总量、空闲量、可用量，以及 `卷已用 - 扫描根目录已知报告占用`。卷统计由实际扫描进程打开根目录后通过 `fstatfs` 采样，记录采样时间。差额始终针对扫描根目录，进入子目录后仍保留该范围，不能当作可清理量。子目录、共享存储、权限缺口、其他挂载、文件系统元数据及采样期间变化都会影响差额。旧会话没有卷采样时明确显示不可计算；扫描或聚合未结束时不计算差额。

## 查询与存储

- SQLite schema 从 1/2 非破坏迁移至 3，添加会话卷采样字段和最近会话索引；历史节点保持不变。
- 扫描增量协议升至 v3，新增有界的 Volume 帧；普通/root 共用解析器。v1 原型回归协议保留。
- JSON 查询增加 `recent`、`ancestors` 和 `volumes`。最近会话最多 20 条；祖先最多 513 条；`volumes` 在普通身份的桥接 IO 线程读取 StorageManager。
- `large-files` 的 `parentId` 限定当前目录范围。子树通过原始路径 BLOB 的前缀范围访问 `node_path` 索引，再按容量排序，不构造 Dart 子树集合。
- 双向 keyset 游标包含方向、查询签名、revision 和稳定并列键；不使用 OFFSET，也不保留无界历史游标栈。
- 列表、根汇总、目录汇总和面包屑必须来自同一个 revision。扫描期间版本变化则提示刷新；旧分页游标失效时回到第一页。请求序号防止旧目录的迟到结果覆盖新导航。
- 查询在 Android IO/Binder 线程执行；页面扫描期间每 2 秒刷新，退到后台停止轮询，恢复时重新读取。终态 journal 持久化前仍不暴露索引终态。

子树大文件查询需要扫描并排序所选范围，成本随该范围规模增长；本阶段没有重复阶段 5 的百万节点压力测试。深层面包屑横向滚动，超长列表名称省略，完整名称和原始字节在详情可查看。快照保留/删除、树图和增长对比继续属于后续阶段。

## 验证方式

```powershell
. ./.local/android-env.ps1
flutter analyze
flutter test
./tools/phase6/verify.ps1 -Serial '<device-id>'
# 本机已授权 ADB shell root，恢复 APK 使用：
./tools/phase6/verify.ps1 -Serial '<device-id>' -RootInstall
```

设备验证、截图和正常入口 APK 恢复方法见[阶段 6 工具说明](../tools/phase6/README.md)。测试仅创建应用私有的独立样本，并在结束时清理；索引保留扫描时的历史记录，不代表样本路径仍然存在。

## 实测结果

沿用 Xiaomi sheng、Android 16/API 36、KernelSU、arm64、4 KiB 页的测试环境。完成以下检查：

- `flutter analyze`：无问题。
- `flutter test`：20 项通过，覆盖旧扫描行为、卷入口与权限、最近会话入口、迟到响应、游标失效、排序失败重试、路径复制、长名称、360×800 双倍字体及 1280×900 分栏。
- Android 索引 instrumentation：JUnit 报告 `OK (11 tests)`，10 项执行通过、1 项规模参数测试跳过；覆盖 7 项 IndexStore 测试、普通链路/中断恢复及 root 169 节点基线。
- Android 协议单元测试通过；Lint 为 0 错误、8 项警告，涉及存储权限政策、目标 API、开发测试依赖更新、路径及模板配置等现有事项。
- 原生扫描 8 项、增量流式扫描 8 项及管道 3 项回归通过，两个 ABI 均构建成功；新增卷采样断言通过。
- Flutter → Android 目录端到端测试通过，核验 58 节点、50 项前后页、名称排序、嵌套目录下钻、当前子树大文件、祖先链、带换行的真实路径复制、卷采样和最近会话。
- 普通扫描/服务死亡恢复 2 项、JNI 诊断 1 项、root 原始名称/共享入口/取消/进程死亡恢复 2 项设备回归通过。
- 已检查真机 PNG：宽屏列表、详情分栏、容量条、卷差额及转义名称显示正常。正常入口双 ABI debug APK 已构建并恢复安装。

验证日志及截图保存在本机 `.local/phase6/` 与 `.local/phase6-*.log`，均不提交。16 KiB 页真机、其他 Android API、其他 root 管理器的运行矩阵继续留在阶段 9；本阶段没有重新声称这些环境已实测。

后续已在目录和大文件详情中添加“使用其他应用打开”，支持系统文件管理器及兼容查看器；当前路径、临时授权与 Root 限制见[功能说明](external-open.md)。
