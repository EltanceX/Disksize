# 扫描性能：步骤 6 native 与传输改进

2026 年 11 月 18 日。普通与 Root 的增量扫描默认合并逐条元数据与挂载查询，并复用帧缓冲。100,001 节点的普通内部 F2FS 样本，纯遍历中位数由 194 降至 126 ms，遍历加传输由 804 降至 670 ms，完整扫描由 6.889 降至 6.563 秒。完整扫描仍主要花在索引导入。

## 实现

- 每个目录项优先通过一次带 `AT_SYMLINK_NOFOLLOW | AT_NO_AUTOMOUNT` 的 `statx` 读取元数据和 mount ID。仅在所用字段的 mask 全部存在、mount ID 非零，且数值可表示时采用结果。未用 `d_type` 推断类型或跳过查询。
- 不支持或缺字段时回到 `fstatat`。如果已有 `statx` 挂载信息，核验身份后使用；否则用 `O_PATH | O_NOFOLLOW` 打开该条目获取并核对身份，再由 FD 查询挂载，必要时读 `/proc/self/fdinfo`。无法确认挂载的条目仍不进入。遇到 `ENOSYS` 后，本次扫描的逐条查询不再重试 `statx`。根目录、打开的目录 FD 身份及挂载复核和遍历结束时的变化检查沿用原机制。
- 普通和 Root 共用的发送器将节点直接编码进最多 32 KiB 的批缓冲，并复用帧头和目录关闭/问题帧的小缓冲。Kotlin 接收器每条流复用一个 36 B 帧头和 64 KiB payload 缓冲。每帧把读取范围限制为声明长度，节点的名称、链接目标、设备和 inode 字节仍独立持有。
- 帧格式仍为 v4，节点批上限仍为 256 条，目录关闭、问题和进度仍按原顺序 flush。保留 UUID、序号、长度、终止顺序及计数校验。没有调整取消、pipe 背压、硬链接 owner、SQLite schema 或快照格式。Root 的正式 Binder 扫描入口沿用原签名，基准变体使用独立入口。

## 测量

与[步骤 5](./scan-performance-finalize.md)使用同一台 Xiaomi sheng（Android 16、arm64、内部 F2FS）。同组使用同一个 Profile APK、同一棵固定空文件树，预热 1 次后轮换策略顺序；主库每次重建，未主动清文件系统缓存。所有 C 组固定 `4096-eager-list` 导入和 `optimized` 最终处理。这里的 `baseline` 是本构建中关闭两项流水线优化的对照。没有扫描实时 `/data/data`。

### 查询次数

独立的模式 A 诊断组（每种策略 3 次），只计逐条路径查询，不含目录 FD 身份/挂载核验、根查询或遍历结束检查。时间为累计经过时间的中位数，含逐条诊断的计时成本。

| 策略 | `fstatat` 次数 / 耗时 | `statx` 次数 / 耗时 | FD 挂载回退 |
| --- | ---: | ---: | ---: |
| `baseline` | 100,000 / 109.0 ms | 100,000 / 70.3 ms | 0 |
| `optimized` | 0 / 0 ms | 100,000 / 101.6 ms | 0 |

### 普通内部 F2FS

未启用逐条计时或资源采样。每行预热后正式测量 5 次。数值为中位数［最小，最大］，单位为秒。

| 流水线策略 | A：纯遍历 | B：遍历、pipe 与解码 | C：完整扫描 |
| --- | ---: | ---: | ---: |
| `baseline` | 0.194 [0.183, 0.215] | 0.804 [0.800, 0.823] | 6.889 [6.628, 7.022] |
| `metadata` | 0.131 [0.125, 0.131] | 0.729 [0.716, 0.744] | — |
| `transport` | 0.192 [0.187, 0.205] | 0.727 [0.701, 0.768] | — |
| `optimized` | 0.126 [0.116, 0.132] | 0.670 [0.622, 0.694] | 6.563 [6.154, 6.655] |

A 不经过传输，`baseline` 与 `transport` 在 A 中执行相同的工作，`metadata` 与 `optimized` 同理。B 只开启其中任一项均比基线快，组合中位数降低 16.6%。B 的普通进程 CPU 中位数由 1.175 降至 1.019 秒。C 的中位数降低 4.7%，两策略范围略有重叠；SQLite 导入仍约 5.5 秒，纯遍历只占完整扫描的一小部分。本步保留单线程，并未改变批量大小或进度频率。

普通组 C 的读帧时间中位数从 630 降到 331 ms（包含等待），解码时间仍约 267 ms。大文件首页由 34.7 到 39.2 ms，范围有重叠；末页约 13 ms。主库和 WAL 终态长度在同树策略间相同。

### Root 内部 F2FS 与普通 FUSE

各组正式测量 3 次，未启用资源采样。单位为秒。

| 后端与模式 | `baseline`［最小，最大］ | `optimized`［最小，最大］ |
| --- | ---: | ---: |
| Root 内部 A | 0.223 [0.219, 0.270] | 0.164 [0.144, 0.179] |
| Root 内部 B | 0.603 [0.597, 0.609] | 0.450 [0.445, 0.455] |
| Root 内部 C | 6.878 [6.849, 6.961] | 6.503 [5.937, 6.526] |
| 普通 FUSE A | 0.660 [0.647, 0.685] | 0.407 [0.401, 0.411] |
| 普通 FUSE B | 1.273 [1.272, 1.281] | 0.980 [0.962, 0.984] |

内部样本各策略均只有 2 个同时打开的遍历 FD，终态为 0。节点 100,001 个，0 个问题、0 逻辑字节，Root 内部报告 4,136,960 分配字节，C 完整性一致。Root C 优化后流水线仍约 6.06 秒，发送方写 pipe 时约 5.81 秒，绝大部分是 `poll` 等待；这些是嵌套的经过时间。加遍历 worker 不能解除当前消费者背压，未进入并发实验。

### Root C 独立资源采样

同规模内部树，每项正式测量 3 次，约每 1.2 秒采集一次。CPU 为窗口内首末样点的计数差，内存、FD 与 WAL 为每次采样峰值的中位数。

| 指标 | `baseline` | `optimized` |
| --- | ---: | ---: |
| 完整扫描［最小，最大］（秒） | 6.795 [6.780, 6.887] | 6.351 [5.957, 6.484] |
| 服务 / Root 扫描进程 CPU（秒） | 4.88 / 0.45 | 5.03 / 0.23 |
| 服务 RSS / PSS（MiB） | 202.3 / 105.8 | 210.7 / 113.8 |
| Root 扫描进程 RSS / PSS（MiB） | 180.6 / 63.1 | 179.5 / 63.2 |
| 服务 / Root 扫描进程 FD | 126 / 96 | 126 / 96 |
| 采样 WAL 最大长度（MiB） | 3.25 | 3.65 |

服务内存的采样中位数上升，三次结果的范围仍有重叠（PSS 99.9–111.9 与 103.5–116.8 MiB）。采样不保证捕捉瞬时峰值。Root 进程的采样跨度也从约 6.00 秒缩到 4.84 秒，不能据表格直接推算整机 CPU 占比。两组终态数据库与 WAL 长度分别为约 90.5 和 0.50 MiB。

## 验证

- arm64 和 x86_64 的 Profile、Debug 及原生测试程序均构建通过；Android Lint 和 JVM 协议测试通过。
- 真机原生扫描、流式扫描和 Root pipe 测试通过。逐字段比较合并查询、分开查询及强制使用 FD/fdinfo 的结果，覆盖原始字节名称、硬链接、稀疏文件、软链接、FIFO、同设备绑定挂载和目录替换，检查取消、节点上限及 FD 回收。新旧发送器在固定输入上逐字节比较 v4 帧（浮动计时字段除外），覆盖条数与字节两种批量上限。
- 最终 APK 的 10,001 节点 A/B/C/Replay 冒烟通过。真机索引、快照及服务回归共 32 项通过、3 项未启用，覆盖分片读入、畸形或截断帧、Root 固定小样本、取消、进程死亡后恢复与历史快照。主 APK 和测试 APK 均恢复到测试前版本，拉回核对 SHA-256 一致。

## 回退与后续

正式 APK 选择两项都启用。要复测或隔离问题，用[基准工具](../tools/scan-performance/README.md)的 `-PipelineVariant baseline,metadata,transport,optimized`。需在正式构建回退时，可以撤回本步骤的流水线改动；旧库和保留快照无需迁移。
