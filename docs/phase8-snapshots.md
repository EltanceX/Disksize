# 阶段 8：快照与增长对比

日期：2026-11-17

## 使用

首页右上角“快照与增长对比”进入快照库。扫描最终聚合完成后自动保存，不需要重新扫描来保存快照；完整结果和 Partial 结果分别标注。先选“设为基准”，再在另一条记录点击“作为新快照对比”。方向由用户选择决定，可以查看逻辑大小或报告占用，并筛选新增、删除、容量 / 类型变化、未知、增长最多的目录。

快照记录扫描开始与结束时间，表示期间观察到的文件元数据，并非文件系统原子快照。重命名按删除和新增展示，不识别移动或文件内容变化。增长目录按新快照中仍为目录的路径排序；目录差额包含其子目录，父子目录不能再次相加。

“保留快照”持久保存保护标记，服务重开后仍有效；删除前必须取消保留。应用不自动淘汰快照。删除对话框确认后，仅清理所选快照的应用侧 session、nodes、aggregates、issues、hardlinks 和一次性对比缓存；不会读取、删除或改变扫描目标。若删除当前最近结果，也清除对应的应用侧会话 journal。其他会话保持可浏览。SQLite 释放的页可复用，本阶段不执行 VACUUM，不保证数据库文件立即缩小。

点击“一键删除快照”进入批量选择，默认选中所有非保留快照，包含“更早快照”中的记录。可逐项取消勾选，或取消全选后自行选择；翻页保留选择。已保留记录显示为禁用的未选中项。点击“删除所选”确认范围后执行，完成显示实际删除份数；删除中的重复操作和页面返回暂时禁用，选择状态下返回则退出选择。

批量操作逐页读取、逐份调用既有删除接口，仅持有当前页与用户选择的例外 ID。执行前重新读取保留状态，底层事务仍检查保留标记。失败时停止后续删除，显示已完成份数与错误，刷新列表并保留剩余选择供重试；此前成功删除的记录不会回滚。被删除的对比基准会同时清空。

## 不可变结果与兼容性

schema 升至 4，保留 schema 1/2/3 原有索引及快照。快照锚定已完成索引的 session ID、revision、最终容量和完整性，不复制一遍整棵树。正常接口不修改快照源数据，重复 finalize 会被拒绝；只有保留标记可以更新，删除是单独操作。取消、中断、失败和仍在扫描的索引不作为最终快照。服务终态 journal 尚未发布时，不允许对比、保留或删除该扫描。

比较前核验：

- 根路径与普通 / Root 模式一致。
- Android 应用用户一致。
- 统计规则一致：原生 v3、路径最小值决定硬链接归属、512 字节 blocks、不跟随符号链接、单挂载、节点与深度上限。
- Android StorageManager.getUuidForPath 返回的稳定卷 UUID 一致，文件系统类型一致。
- 系统无法提供 UUID 时，要求根节点设备号、扫描挂载和已知启动标识一致，避免重启后重用设备号造成错误匹配。优先使用 boot_id，受限时使用 Android boot_count。
- 快照 revision 仍与最终索引相符。

系统提供稳定卷 UUID 的路径可以跨启动和挂载 ID 变化比较；没有 UUID 的路径采用保守限制，跨启动、挂载改变或身份未知时明确拒绝比较。旧索引仍可浏览、保留、删除，但缺少扫描身份 / 规则时需要重新扫描才能参与对比。不会根据路径看起来相同就推断兼容。

## 路径匹配与未知范围

用原始字节相对路径匹配，不依赖每次扫描的 node ID、遍历顺序、UTF-8 解码或 inode 作为跨快照键。容量直接取既有最终聚合，保留目录自身占用、稀疏文件与确定性硬链接归属语义。路径中的换行等控制字符沿用转义显示；无法解码的不同原始名称仍分别匹配。

两侧条目都存在时，仅在元数据有效、没有主动跳过且子树完整时确认容量差额。单侧缺失时，沿原始路径查找另一快照中最近的实际祖先：目录必须元数据有效、正常完成且已完整枚举，才能确认该路径不存在；若祖先已变为完整的非目录条目，也可确认其后代不存在。祖先不可访问、枚举失败、主动跳过或元数据未知时，该缺失条目标记“未知”，不能当作删除或新增。

使用目录的本地枚举状态判断缺失，不因其他兄弟子树有错误而把整个范围全部判为未知。匹配项目的目录容量仍要求整个聚合子树完整。任一快照 Partial 时，总差额显示未知，路径列表保留可确认的局部变化；已知量之差不会作为真实净增长。

## 有界计算与协议

复用 Pigeon / Binder 的 JSON queryIndex，新增 snapshot-list、snapshot-retain、snapshot-delete、snapshot-compare。没有增加 root 文件写入接口，也没有变更原生 v3 协议。

服务在 SQLite 中保留一组可丢弃的对比缓存。两侧按 BLOB 路径顺序归并，各持有最多 16 条节点；每个请求最多处理 512 个路径，并在约 200 ms 后的条目边界返回进度。缺失范围使用索引精确查找祖先，缓存最多 32 项且最多 1 MiB。不能假定 BLOB 路径顺序是树的前序，例如 a- 会排在 a 和 a/file 之间。

未完成计算返回 building，页面显示进度并继续请求，退出页面后停止驱动。服务进程丢失内存状态时，下次对比从源快照重建缓存；不会把半成品当作完整结果。切换对比组合会替换缓存，删除快照会使缓存失效。写操作采用 SQLite 非独占事务，与扫描导入的写事务串行化。

快照库默认每页 20 条、API 最多 50 条；对比默认每页 50 条、API 最多 100 条，响应条目另有约 384 KB 的文本预算。容量排序以原始路径作为稳定并列键；游标绑定两个快照、revision、筛选、口径和页大小。游标使用缓存行 ID，深路径不会生成超过 Binder 请求上限的长游标。Dart 仅持有当前页面。

命令与恢复步骤见[阶段 8 工具说明](../tools/phase8/README.md)。运行环境沿用 Xiaomi sheng、Android 16/API 36、arm64、4 KiB 页、KernelSU；通过已授权 su 覆盖安装，保留历史扫描。

- Flutter 静态分析无问题；35 项 Flutter 测试通过，新增 5 项覆盖基准选择、未知总额、转义名称、保留 / 删除、分批计算、兼容性说明，以及 360×800 双倍字号和 1280×900 布局。
- 21 项真机索引测试通过，覆盖真实新增、删除与容量变化、旧快照保持不变、删除不影响目标、不可访问与跳过范围双向对比、类型替换、近似前缀、硬链接乱序、身份与规则不兼容、容量并列及未知差额分页、保留持久化、schema 1/2/3 升级、无效 UTF-8 名称、计算状态丢失后的重建与深路径响应预算。确认自身目录可取得稳定卷 UUID；通过构造不同 boot / mount 元数据，验证 UUID 相同允许比较、UUID 不同明确拒绝，未实际重启设备。
- profile 端到端测试通过：新增 7 B、删除 5 B、文件及 Cache 子树增长 6 B，总增长 8 B；确认旧快照仍为 7 B、保留快照拒绝删除、清理后目标文件内容仍为 8 B、当前 journal 被清除。两次扫描、Pigeon、Binder、SQLite 和 Flutter 页面均使用真实实现。
- 双 ABI debug 与 profile APK 已构建；正常入口 APK 已恢复安装。对比页真机 PNG 已检查，位于忽略目录 .local/phase8/comparison.png。
- 4 项 JVM 协议测试通过；Android Lint 0 错误、8 项既有警告。

本阶段不声称已测量百万节点快照对比、超大索引删除时延、其他设备或真实跨启动卷匹配。对比缓存大小随变化路径数增长，快照总空间随保留扫描数增长；规模、其他 Android 版本和正式交付矩阵继续属于阶段 9。
