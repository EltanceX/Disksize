# 阶段 2：只读扫描核心原型

日期：2026-11-15

状态：阶段 2 已完成。arm64 真机原生测试 8 组通过、无失败或跳过；arm64-v8a/x86_64 构建通过。

## 1. 交付范围

提供不依赖 Flutter、JNI 或 root 框架的 C++20 扫描核心，以及独立 CLI 和设备原生测试。Android 原生库与独立工具使用同一个 `disksize_core` CMake target。

本阶段的 root 执行仅用于命令行验收，使用设备已经授权的 `su`，尚未实现应用 RootService。Flutter 首页继续提供阶段 1 的运行环境检查；普通扫描任务、权限和生命周期在阶段 3 接入，应用 root 后端在阶段 4 接入，索引落盘在阶段 5 接入。

## 2. 调用与数据约定

同步入口为 `scan_directory(configuration, cancellation, callbacks)`，调用方应在工作线程执行。扫描内部默认使用两个遍历线程；返回 `ScanResult`，包含节点、问题、最终容量和资源指标。

每个节点获得会话内连续的 64 位 ID，父节点先于子节点产生。ID 不承诺跨扫描稳定；路径字节用于确定性硬链接归属。节点保存原始名称、链接目标、父节点、类型、UID/GID、mode、设备/inode/挂载 ID、原始大小、计入大小、子树聚合、问题数和完整性。

回调为 `on_nodes(span)`、`on_progress` 和 `on_issue`。所有回调串行、同步执行，回调返回形成背压；回调应及时返回。目录的发现回调返回后才可调度该目录。回调抛异常会停止生产并返回 Failed/ConsumerFailure。回调中的发现节点尚无最终聚合和硬链接归属，应使用返回结果中的最终节点。

默认配置：

| 参数 | 默认值 |
| --- | --- |
| 遍历线程 | 2，支持 1～8 |
| 待执行队列 | 128，支持 1～4096 |
| 节点批次 | 256，支持 1～4096 |
| 目录最大深度 | 512，根深度为 0，配置上限 4096 |
| 最大节点数 | 1,000,000 |
| 保留问题记录数 | 4096，超过后继续累计总数和 dropped_issues |
| 进度合并间隔 | 150 ms；开始和结束强制报告 |

协调器将节点中的待扫描目录状态送入有界队列，工作线程只发现节点，不阻塞地向同一满队列追加子目录，从而避免宽目录下的生产者死锁。队列之外的待调度状态仍属于内存节点索引。

此原型保留 O(N) 节点和最终聚合数据，并不是百万节点持久化方案；默认节点上限防止无限增长，不代表百万节点内存表现已验收。阶段 5 再实现事务写入、持久索引、分页和规模测量。

## 3. 统计与完整性

- 逻辑大小仅累计普通文件 `st_size`，使用 64 位无符号计数。
- 报告占用量为 `st_blocks × 512`，包含目录、符号链接和特殊文件自身的分配量。它不是物理块共享、压缩或 reflink 的精确分摊。
- `(st_dev, st_ino)` 相同的非目录项去重，包括硬链接到符号链接的目录项。按扫描根内完整相对路径的**无符号原始字节顺序**选择最小路径为归属节点；其余节点保留原始大小，但计入量为 0，并指向归属 ID。
- 目录自身报告占用量加其后代计入量形成子树占用，目录自身 `st_size` 不计入逻辑容量。父先子后的节点顺序允许逆序聚合。
- 发现进度中的 `observed_logical_bytes` 是未去重的暂定观察量，不提供虚构百分比；最终数字读取 summary。
- 权限拒绝、消失、I/O、资源上限、消费者失败和扫描期间变更分别分类。不可枚举目录保留元数据及 `directory_enumerated=false`、`complete=false`，子树容量只表示已知部分。
- 主动跳过范围或任一后代不完整会传播为 Partial。取消返回 Cancelled；根无法打开、配置错误或工作线程/消费者失败返回 Failed。这些状态的根均不标为 complete。
- 同一 inode 的硬链接观察到不同大小或 mtime 会记变更问题；动态扫描仍不是原子快照，也不能保证发现全部并发修改。

扫描器不写被扫描文件内容、不修改权限或所有者；文件系统本身可能更新目录访问时间。测试对内容、大小、分配量、mode、UID/GID、inode 和 mtime 做前后核对，不把 atime 不变作为承诺。

## 4. 遍历与边界

用户显式选择的根路径先 `realpath` 一次，以支持 `/sdcard` 等选择别名；随后逐组件使用 `O_PATH | O_DIRECTORY | O_NOFOLLOW` 打开祖先，最终仅打开根目录读取目录项。祖先只需要搜索权限，不要求可列举 `/data` 等父目录。

发现项通过 `fstatat(AT_SYMLINK_NOFOLLOW)` 读取元数据，符号链接仅由 `readlinkat` 读取原始目标文本，不进入目标。普通文件内容从不读取，FIFO 也不会被以内容读取模式打开。遇到零读取权限的普通文件仍可统计可见元数据。

待扫描目录不持有整条祖先 FD 链；相对固定根 FD 重新逐组件打开，并校验各级设备/inode 和挂载身份，限制同时打开的 FD。祖先被替换为符号链接或其他 inode 时返回变更问题，不沿替代路径进入外部目录。深层后代路径不依赖拼出完整路径调用 `open()`；显式根路径解析仍受平台 `realpath` 限制。

挂载身份优先使用直接 `statx` 系统调用的 `STATX_MNT_ID`，不支持时使用元数据专用 `O_PATH` FD 和 `/proc/self/fdinfo`。逐项识别挂载身份，目录 bind mount 和普通文件 bind mount 即使 `st_dev` 相同也会排除；身份无法确认时记录不完整，不默默穿越。所选根挂载 ID 是本次进程视图的记录，不能作为跨设备或跨重启的永久卷标识。

显式排除 `/proc`、`/sys`、`/dev` 子树；同时按文件系统 magic 排除 proc/sysfs/cgroup/securityfs/debugfs/tracefs 等伪文件系统。根选中此类范围时保留跳过节点并返回 Partial。

当前仅实现**单个选定挂载、不跟随发现项符号链接**。配置请求 `cross_mount_points=true` 或 `follow_symbolic_links=true` 时明确返回 Unsupported。取消在目录/条目/路径组件边界检查；阻塞的内核 I/O 或未返回的消费者回调仍可能延迟停止。

## 5. 验证与复现

命令和工具约定见[阶段 2 工具说明](../tools/phase2/README.md)：

```powershell
. ./.local/android-env.ps1
./tools/phase2/verify.ps1 -Serial '<device-id>' `
  -BaselineRoot '/data/local/tmp/disksize-phase0/run-20261115-02' `
  -BaselineShared '/sdcard/Download/DiskSize-phase0/run-20261115-02'
```

不传基线参数时仍执行完整原生测试。测试创建并清理自己的临时样本，不改变已有阶段 0 样本。挂载测试仅在新建 private 挂载命名空间中操作本次样本；本机实际成功执行，无跳过。

实测设备沿用阶段 0：Xiaomi sheng、Android 16/API 36、arm64、4 KiB 页，`/data` 为 F2FS，共享存储为 FUSE，KernelSU 3.3.0。SELinux 始终 Enforcing。

8 组原生测试全部通过：

1. 5 GiB 稀疏文件、普通文件/硬链接/硬链接符号链接、FIFO、链接循环、空目录、Unicode/空格/换行/非法 UTF-8 名称；独立 lstat 去重分配量；1/2 线程归属一致；无符号字节排序；源内容和元数据保持。
2. 240 个子目录和 240 个文件，在队列容量 1 下完成；节点上限、深度上限、问题记录截断和完整性传播。
3. 80 层目录、相对路径超过 4096 字节，进程 FD 软上限降至 48 后连续扫描 8 次；检查队列/线程/FD 峰值、退出时 tracked FD 为 0、进程 FD 数无泄漏。
4. 批次回调请求取消、启动前取消、消费者异常，均正确收尾并释放 FD。阶段 3 另补 40 次外部线程取消并修复协调器唤醒竞争，回归通过。
5. 目录发现后被删除、祖先被替换为外部符号链接，返回 Partial 且不扫描外部哨兵文件。
6. 子进程降至 UID/GID 2000 后验证权限拒绝、无文件读取权限时的元数据扫描，以及只有搜索权限的祖先目录。
7. 伪文件系统排除、无效配置、不支持策略、根不存在，以及显式选择根别名的解析。
8. private 命名空间内的同设备目录 bind mount 和文件 bind mount 边界，均无重复累计。

独立 C++ 核心、CLI、测试均用 NDK Clang 的 `-Wall -Wextra -Werror` 构建，两种 ABI 通过。Android 双 ABI debug APK 构建通过；现有 Flutter → Pigeon → Binder → 独立服务 → JNI 的真机集成测试回归通过。最终设备恢复普通应用入口。
